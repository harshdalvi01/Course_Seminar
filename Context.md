# Context

## Project Title
AI-Native Software Engineering

## Subtitle
Redesigning the Software Development Lifecycle Around Autonomous AI Agents

## Problem Statement
Traditional software engineering involves extensive manual effort in writing boilerplate code, creating boilerplate documentation, and performing routine tests. While AI tools exist, they are often used in an ad-hoc manner as "assistants" rather than being deeply integrated into a structured Software Development Lifecycle (SDLC). There is a lack of structured frameworks where AI agents autonomously handle the generation of artifacts at each stage of the SDLC while humans remain in a purely governance and validation role.

## Objective
Build a Django-based academic prototype demonstrating an AI-native software engineering workflow. The system will guide a natural-language software idea through a complete SDLC driven by specialized AI agents, validated by a secondary AI system, and approved by a human at every stage.

## Target Users
- Software Engineers exploring AI-native workflows.
- Technical Project Managers interested in automated SDLCs.
- Academic Researchers studying human-AI collaboration in software engineering.

## Prototype Scope
The application will track projects through various stages: Idea -> Requirements -> Design -> Code -> Testing -> Deployment. It will support human-in-the-loop interactions including approving, rejecting, editing, and regenerating AI-created artifacts, while preserving artifact version history.

## Technology Stack
- **Backend:** Python, Django
- **Frontend:** HTML, CSS, Vanilla JavaScript
- **Database:** SQLite
- **AI Generation:** Groq API
- **AI Validation:** Jev / TypeSafe AI API
- **Authentication:** Django built-in authentication

## SDLC Stages
1. **Idea:** Natural-language concept submitted by the user.
2. **Requirements:** Detailed requirements generation.
3. **Design:** Architectural and technical design generation.
4. **Code:** Source code generation based on design.
5. **Testing:** Test plan and requirement coverage analysis.
6. **Deployment:** Deployment strategy and CI/CD recommendations.

## Roles
- **Role of Groq:** Generates content and artifacts for each SDLC stage (Requirements, Design, Code, Test Plans, Deployment Plans).
- **Role of Jev:** Provides structured validation and decision support for the artifacts generated by Groq (e.g., checking for completeness, consistency, security).
- **Role of Humans:** Provides final governance and approval. Humans review the AI-generated artifact and the AI-generated validation report, then make the final decision to approve, reject, edit, or regenerate.

## Core Terminology & Distinction
**AI-Assisted vs. AI-Native Software Engineering**
An AI-assisted approach treats AI as a tool (like a smart autocomplete or chatbot) that a human developer uses while actively writing code or documentation. 

"An AI-native software engineering approach treats AI agents as active participants across the software development lifecycle, while humans remain responsible for validation, governance and critical decisions."

## Important Constraints & Excluded Functionality
- **NO execution of AI-generated source code.**
- **NO automatic installation of generated dependencies.**
- **NO running arbitrary generated scripts.**
- **NO automatic deployment of applications.**
- **NO bypassing human approval.**
- **NO overwriting historical artifacts.**
- **NO passing unapproved artifacts to later stages.**
- **NO microservices or unnecessary frontend frameworks (e.g., React).**
