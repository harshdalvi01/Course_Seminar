# Human-in-the-Loop (HITL) Specification

## Core Principle
"AI proposes and automates; humans validate, guide and remain accountable."

## Overview
Every artifact generated by the AI must undergo human review before the project can advance to the next SDLC stage. The user is presented with the generated artifact alongside the Jev validation report to support their decision.

## Review Operations

### 1. APPROVE
- **Action:** The human accepts the artifact as-is (or after their own manual edits).
- **System Behavior:** 
  - Marks the specific artifact version as `approved`.
  - Records a Review entry in the database.
  - Advances the `Project.current_stage` to the next SDLC phase.
  - The approved artifact is now locked as immutable context for downstream agents.

### 2. EDIT
- **Action:** The human manually modifies the AI-generated artifact text.
- **System Behavior:**
  - Creates a *new version* of the artifact (e.g., v2).
  - Preserves the old version (e.g., v1).
  - Records the human as the author of the changes.
  - The project state does not advance until the human clicks APPROVE on their new version.

### 3. REJECT
- **Action:** The human completely rejects the artifact and does not want to automatically regenerate it immediately, or wants to stall progress.
- **System Behavior:**
  - Requires the user to input feedback/reasoning.
  - Records the Review entry.
  - Project state does not advance. 
  - Artifact is marked rejected.

### 4. REGENERATE
- **Action:** The human rejects the current artifact and requests a new version from the AI based on feedback.
- **System Behavior:**
  - Requires the user to input feedback/reasoning.
  - Calls the Groq agent again, appending the human feedback to the prompt.
  - Creates a *new version* of the artifact.
  - Calls Jev to validate the new version.
  - Presents the new version to the user for review.

## Version History and Auditability
- Every generation and every edit increments the version number.
- Users can view a "History" tab for any stage (e.g., seeing how Requirements evolved from v1 to v4 before approval).
- The database securely links every Review action to a specific User and Timestamp, ensuring full auditability of who approved what and when.
