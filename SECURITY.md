# Security Requirements

## Overview
Because this system generates software code autonomously, strict security boundaries are required to protect the host server, the users, and the integrity of the data.

## Critical Prohibition Rules
- **AI-generated code must NEVER automatically execute on the server.**
- **The system must NEVER automatically install generated dependencies.**
- **The system must NEVER automatically deploy generated applications.**

## System Security

### API Key Management
- Groq and Jev API keys must be stored in secure environment variables (e.g., `.env` file).
- API keys must **never** be exposed to the browser or sent to the frontend. All API calls must occur server-side within Django views/services.

### Django Application Security
- **Authentication:** Utilize Django's robust built-in authentication system for user sessions.
- **Authorization:** Implement object-level permissions. A user can only access, view, or modify Projects they own.
- **CSRF Protection:** Django's CSRF middleware must be active for all POST/PUT/DELETE requests.
- **Input Validation:** All user inputs (project ideas, human feedback, artifact edits) must be sanitized and validated before database insertion or passing to AI models.
- **Output Validation:** HTML generated by AI must be properly escaped in templates to prevent XSS when rendering artifacts.

## AI-Specific Risks

### Prompt Injection Considerations
- User inputs (Idea, Feedback) are passed into system prompts. Instructions must clearly delineate user input from system instructions to mitigate prompt injection attempts aimed at bypassing constraints.

### AI-Generated Code Risks
- The Coding Agent generates source code. This code is treated as plain text data by the Django application. It is stored in the database and rendered in the browser. It is never `eval()`'d or written to executable directories on the host machine.

### Logging and Error Handling
- All interactions with Groq and Jev APIs must be logged (excluding sensitive user data where possible).
- API failures, timeouts, or rate limits must be caught gracefully and presented to the user with clear instructions, rather than crashing the application.
